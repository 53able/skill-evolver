# Experiment protocol

Run Python commands through uv. Prepare the dependency-free checkout with `uv sync --locked`, then use `PYTHONPATH=src uv run --locked python -m skill_evolver ...`. Run the complete container-backed test suite with `SKILL_EVOLVER_DOCKER_TESTS=1 PYTHONPATH=src uv run --locked python -m unittest discover -s tests -v`. The uv project does not install an editable package; the `src` import path is explicit. See the README for CLI commands and optional wheel installation through `uv pip`.

This implementation is a local experimental harness. The bundled deterministic mock model performs an `uppercase` operation with real Docker tools, independent of candidate quality. Its synthetic token accounting and zero billed USD verify execution. Evaluate skill quality with real models and held-out tasks. Unsupported providers fail closed; the configured OpenAI path is described below. No credentials or real model calls are required for the fixture.

Each run freezes its configuration, source hash, split definitions, model/options and pricing version in `experiment.json`. The source skill is read-only from the harness perspective and checked before and after every trial. Only candidate bodies change; frontmatter is byte-preserved. Local bundled file references fail closed because the runner currently stages skill text only. Local anchor references are checked. There is no automatic installation or application of a candidate.

Cases must have disjoint IDs and group IDs across search, selection and final splits. Exact public-task fingerprints (prompt, files, operation, output_paths) cannot cross splits. Assign semantic near-duplicates to the same group before splitting; validation checks exact overlap only. The fixture uses three cases per split. The planned quality experiment uses 12 search, 8 selection and 20 final cases.

Experiment/case/group IDs are nonempty safe strings matching `[A-Za-z0-9][A-Za-z0-9_-]{0,127}`. Numeric IDs, separators and control characters are rejected before journal identities are constructed, so distinct accepted case IDs cannot collide through string coercion or path ambiguity.

Original, sequential and GA each receive the same separate search, selection and final budgets for each independent search. Search includes each method's original measurement, every evaluation/retry, and synthetic zero-cost semantic proposals. A conservative complete-trial token envelope is reserved before execution, covering every bounded model step; known usage is then settled. Unknown usage retains the full reservation. Money is zero for the mock provider; real calls use configured token-rate accounting. Original, incumbent, elite and duplicate candidates use the same completed candidate/case/repeat cache within a method/search; caches are never shared across methods/searches. Only candidates that complete every planned evaluation enter ranking. If the budget expires before the original finishes, the experiment is incomplete. A fully evaluated original remains eligible when execution has no unresolved uncertainty.

Sequential search keeps an incumbent and replaces it only when the common ranking improves. GA starts from the original plus mutations, uses tournament size two, preserves two elites and applies matching-section crossover with probability 0.5 followed by one mutation. Unheaded bodies skip crossover. Population, generations, independent searches and seed are frozen in configuration. Synthetic proposals test mutation mechanics without access to hidden cases or answers.

All valid fully evaluated candidates are ranked by success rate, then run tokens, then body length (hash breaks exact ties deterministically). All method/search top-three candidate lists are frozen before selection starts. All winners are fixed before final cases are evaluated. Selection/final repeats are three; search repeats are one. Selection information never feeds proposals. Infrastructure errors retry once, while task failure/timeout remain zero scores. Unresolved infrastructure or indeterminate trials make the comparison incomplete.

A fsynced single-writer JSONL journal records reservations, results, settlements, synthetic proposals, frozen lists and winners. Atomic snapshots contain immutable manifests/candidates and the completion marker. Interrupted calls without a durable result become indeterminate with planned identifiers; reservations remain charged and calls are not repeated. A durable result recovered before settlement is settled from its recorded usage. Resume marks calls without durable results indeterminate instead of issuing them again. Keep the run directory and source skill available when resuming.

Reports retain all attempts, case outcomes, costs, remaining budget, candidate lineage and diffs. Repeats are averaged per case before paired differences. Bootstrap samples groups uniformly with replacement and retains every case within each sampled group, computing a case-equal mean (10,000 draws, 95% interval). Intervals are conditional on one fixed search; fewer than ten groups yields exploratory intervals only. A zero-containing interval is inconclusive, not equivalence. Every independent search is shown, and a single search leaves search reproducibility unverified. Mock reports always withhold superiority claims.

Method/search validity is separate from final task success. Frozen candidate lists, winners and completion records carry validity snapshots; report generation independently reduces the complete journal rather than trusting those summaries. An initial infrastructure error followed by the permitted successful retry resolves that planned trial. Exhausted infrastructure retries, indeterminate search calls/proposals and reservations without durable execution outcomes make that method/search incomplete, including after resume. Unknown reservations remain charged. When the budget expires without unresolved execution uncertainty, the fully evaluated original remains eligible for selection. Conditional improvement cannot be reported from an uncertain search, even with otherwise successful final trials and enough bootstrap groups.

Before any trial, the runner resolves and freezes an immutable Docker image ID in the experiment manifest independently of the input configuration fingerprint. Resume must verify and use that exact ID; it cannot re-resolve a mutable tag as a replacement. The first comparable observed environment hash is atomically persisted before ranking, and mismatches are recorded as indeterminate/incomplete. Reports also reject historical mixed hashes or absent runtime freezes. Historical manifests without the immutable image ID cannot be resumed as valid experiments; their earlier evidence remains historical and a fresh run is required.

The runner records exact nonce-associated resource allocations in the fsynced journal before creation and releases after cleanup. After manifest identity verification, orchestration invokes the runner's verified recovery on the complete event history before making new calls. Recovery ownership/label checks, execution-time storage bounds and daemon-enforced resource lifetimes are the sandbox layer's responsibility; the core supplies no host-execution or broad-prefix cleanup fallback.

## Configured real-model path

The supported real provider is OpenAI Responses via a standard-library host broker, with exact `/v1/responses/input_tokens` preflight and the same request framing for generation. Both roles require an explicit supported model ID, empty options, host `api_key_env`, and `count_fee_acknowledged: true`. A positive configured unified input/output token rate and pricing version are mandatory. Validation does not read credentials or call APIs. The monetary budget applies to the configured token rate. Check token-count request fees and provider billing separately before choosing that rate and budget.

Real candidate proposals reserve one complete input/output envelope before calling the broker. GA first performs matching-section crossover in code (or records the no-section skip), then asks for one body mutation. The proposal context contains immutable original frontmatter, the current/crossed body, optional donor body and search-only failure transcripts. It never contains selection/final observations or expected outputs. Invalid mutations retain known paid usage; unknown usage retains the full reservation. Exact candidate results are durable before selection/evaluation, and resume reuses them rather than generating again. Unexpected programming failures propagate while leaving the reservation recoverable. API transport/usage errors are handled only through the documented `ModelError` contract.

Reports derive mock status from both configured roles. Any mock role keeps the plumbing-only disclaimer. A fully real report records improvement for its fixed skill, models and search only when both GA-minus-original and GA-minus-sequential intervals have positive lower bounds, at least ten independent groups and complete data. Fake-broker tests verify this decision rule. Live API compatibility and real-model effectiveness require a real experiment.
