# ホスト側のOpenAI Responsesアダプター

言語: [English](../model-evidence.md) | 日本語

`OpenAIJSONModel(model_config).complete(context, *, max_input_tokens,
max_output_tokens, timeout_seconds)` は `{content: dict, input_tokens: int,
output_tokens: int, tokens: int}` を返します。`ModelError(message, tokens=...)` は使用量を公開します。推論を伴わないローカル検証・事前検証では0、不正な推論内容では既知の合計値、通信の不確実性、使用量の欠落・不整合、予約枠の異常ではNoneになります。Noneの場合、外側の集計処理は予約を保持する必要があります。

設定には、provider `openai`、空でないid、options `{}`、api_key_env、count_fee_acknowledged `true` が必要です。予算を設定する前に、プロバイダーの価格とカウントリクエストの料金を確認してください。`count_fee_acknowledged` は、この確認要件の承認を記録します。実験では、各役割を設定されたトークン単価で集計します。アダプターは任意のモデルオプション、カスタムURL、インラインAPIキー、リモートの会話参照を拒否します。デフォルトのフィクスチャはモックのままです。

各呼び出しは、自己完結した同一のJSONバイト列を、まず `https://api.openai.com/v1/responses/input_tokens` にPOSTします。有効なカウントがmax_input_tokens以内の場合にだけ、続いて `https://api.openai.com/v1/responses` にPOSTします。リクエストにはmodel、developer/user入力、max_output_tokens、JSONオブジェクトのテキスト形式、stream=false、store=falseを含めます。tools、previous_response_id、conversationは送信しません。そのため、カウントには実際のリクエスト構成とモデルのオーバーヘッドが含まれ、実トークンの上限判定にモックのバイト数推定を使うことはありません。リクエストの上限は1 MiB、レスポンスの上限は4 MiBです。トークンの集計には、入力トークンの事前確認と報告された使用量を使います。自動再試行はありません。

通信は固定APIエンドポイントへのHTTPSだけを使います。リダイレクトと環境のプロキシ設定は無効にします。APIキーは呼び出し時に、指定した環境変数からホスト側で読み取ります。サンドボックスへ渡したり、コンテキストに含めたり、エラーに出力したりすることはありません。リクエストの期限は、カウントと推論の両方を合わせたものです。ソケットのタイムアウトと単調増加時計による確認で読み取り時間を制限し、Unixのメインスレッドのインターバルタイマーで、ブロックするDNS・接続処理や低速な通信も制限します。Unixのメインスレッド以外からの呼び出し、または実時間のインターバルタイマーがすでに稼働している状態での呼び出しは、生成前にtokens=0で失敗します。この制約は現在の同期型Unix CLIに適合し、呼び出し元のタイマー変更を避けます。

推論の使用量は内容より先に検証します。input_tokens/output_tokens/total_tokensは厳密に非負の整数であり、合計が一致する必要があります。推論トークンはすでにoutput_tokensに含まれているため、重ねて加算しません。入力または出力の使用量が予約枠を超えると、tokens=Noneの異常エラーになります。未完了ステータス、拒否、不正なJSON、重複キー、非有限値を含むJSON、オブジェクト以外の内容は、有効な既知の使用量を保持したまま拒否します。assistantのoutput_textはちょうど1つだけ受理し、reasoning出力項目は任意で認めます。

ランナーが送信するのは、公開されたケースのフィールド、スキル、トランスクリプト、アクションの指示だけです。4つのDockerツールを呼び出す前に、各ローカルアクションのスキーマを検証します。skill_loaded=trueには、従来どおりSKILL.mdを読み取った証拠が必要です。既知の実使用量はステップをまたいで合計します。推論の使用量が1つでも不明なら、結果不確定かつtokens=Noneを返し、コアが試行の予約枠全体を保持するようにします。モックの合成集計とシェルによる変換は変更しません。予約量は厳密にmax_steps*(max_input_tokens+max_output_tokens)のままです。

## 検証

すべてのHTTPテストはurllibの通信処理を差し替え、専用の偽の環境変数キー名を使います。実際のAPIキーは読み取らず、実APIや有料APIを呼び出していません。アダプターの10件のテストは、同一ペイロード、事前確認による実行制御、使用量と異常、費用が既知の不正な内容、推論トークンの集計、オプションとキーの検証、リクエスト・レスポンスのバイト数上限、リダイレクト、通信障害、共通の期限、実際の実時間タイマーによる割り込みを対象にしています。ランナーの単体テストは、実トークンの集計、期待される正解の除外、厳密なアクションスキーマ、既知・不明の費用の扱い、SKILLの読み取り証拠を対象にしています。Dockerテストでは引き続き、実際のモック用ツールと隔離境界を検証します。品質実験を始める前に、選択したモデルとトークン数カウントのリクエストを実APIで検証してください。アダプターはAPIエラーを拒否します。
